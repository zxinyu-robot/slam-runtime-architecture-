# 边缘异构空间导航系统

## 1. 文档定位

本文整理边缘异构空间导航系统的总体方案。

系统面向多机器人在局域网、边缘节点和云端协同环境下的空间建图、导航和资源调度问题。

核心目标：

1. 将 SLAM 前端、后端、闭环优化和强化学习决策能力进行分层部署，实现机器人端轻量化、边缘端高精度全局优化、云端持续训练与模型管理。
2. 引入KMZ变种的相关机器人动作管理链接

系统主要采用 C++相关te'x进行工程实现，通信层以 DDS 为基础，不引入 TCP 链路，优先使用 UDP/IP、RTPS、QoS 和共享内存传输能力。视觉或图像帧流使用 x265/FFmpeg 进行高效压缩，边缘节点负责重建、融合、优化和策略推理。

所有节点均采用docker单独容器封装，进行docker编排启动顺序

## 2. 核心目标序

- 机器人端只保留实时性强、资源占用低的 SLAM 前端能力，包括传感器采集、特征提取、里程计估计和局部子图构建。
- 边缘端承担计算密集任务，包括子图拼接、闭环检测、全局位姿图优化、地图融合和多机器人资源调度。
- 云端承担离线训练、仿真评估、模型版本管理和策略分发。
- 通过 PPO 等深度强化学习方法，根据网络状态、计算负载、地图质量和机器人状态动态调整传输参数、压缩率、特征等级和计算卸载比例。
- 通过 DDS QoS、零拷贝共享内存和 x265 编码降低端到端延迟与带宽占用。

## 3. 总体架构

系统采用“云-边-端”三层架构，形成“感知-传输-计算-决策-反馈”的闭环。

```text
┌─────────────────────────────────────────────────────────────────────┐
│                         Cloud Layer                                 │
│  模型训练 | 仿真评估 | 模型版本管理 | A/B 测试 | 数据存储             │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 模型下发 / 经验上传
┌───────────────────────────────▼─────────────────────────────────────┐
│                         Edge Layer                                  │
│  全局地图构建 | 子图融合 | 后端优化 | DRL 推理 | 资源调度 | 质量监控   │
│  DDS 通信总线 + x265 编解码 + QoS 策略 + 安全策略                    │
└───────────────────────────────┬─────────────────────────────────────┘
                                │ 子图上传 / 策略下发
┌───────────────────────────────▼─────────────────────────────────────┐
│                         Robot Layer                                 │
│  传感器采集 | 轻量 SLAM 前端 | 局部子图 | 通信代理 | 本地降级策略      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.1 机器人端

机器人端负责资源敏感型实时任务。

- 采集相机、LiDAR、IMU 等传感器数据。
- 执行视觉里程计、视觉惯性里程计或轻量级 LiDAR 前端。
- 生成关键帧、局部地图点和局部子图。
- 维护机器人自身状态，包括位姿、速度、电量、CPU/GPU/内存负载。
- 通过 DDS 发布子图、关键帧、压缩帧流和状态信息。
- 接收边缘端下发的编码参数、传输频率、特征提取等级和卸载策略。

### 3.2 边缘端

边缘端是系统的实时智能核心。

- 接收多机器人上传的子图、关键帧、帧流和状态信息。
- 进行子图间匹配、相对位姿估计、全局地图融合和闭环检测。
- 使用 Ceres Solver、g2o 或 GTSAM 进行位姿图或因子图优化。
- 运行 PPO 推理引擎，根据系统状态输出资源调度和传输控制策略。
- 采集经验数据并上传云端，用于后续离线训练。
- 维护模型热更新、灰度发布和回滚能力。

### 3.3 云端

云端用于非实时任务和全局训练管理。

- 汇聚边缘端上传的运行日志、状态、动作、奖励和地图质量指标。
- 在 Gazebo、Unity 或自定义仿真环境中构造训练场景。
- 训练、评估和管理 DRL 模型。
- 通过模型注册中心进行版本管理、A/B 测试和回滚。
- 将稳定模型转换为 TorchScript、ONNX 或 TensorRT 可部署格式，下发给边缘端。

## 4. 数据流与控制流

### 4.1 前向数据流

```text
机器人感知
  -> 特征提取 / 里程计估计
  -> 局部子图生成
  -> x265 编码或结构化序列化
  -> DDS 发布
  -> 边缘端接收与解码
  -> 子图融合
  -> 全局后端优化
  -> 地图更新
  -> DRL 状态更新
```

### 4.2 反向控制流

```text
DRL 策略推理
  -> 资源分配策略
  -> 编码参数 / 传输频率 / 卸载比例
  -> DDS 下发
  -> 机器人端接收
  -> 本地参数调整
  -> 自适应感知和传输
```

### 4.3 训练反馈流

```text
运行状态采集
  -> 经验存储
  -> 边缘端定期上传
  -> 云端训练
  -> 模型评估
  -> 版本管理
  -> 模型下发
  -> 边缘端热更新
```

## 5. SLAM 分层处理方案

### 5.1 机器人端轻量前端

机器人端只执行必要的实时估计，避免将全局优化放在低功耗设备上。

- 输入：相机、LiDAR、IMU 等传感器数据。
- 输出：关键帧、局部地图点、局部子图、前端位姿估计和不确定性。
- 典型算法：ORB-SLAM3 前端、VINS-Fusion 前端、LIO-SAM 前端。
- 可动态调整项：特征数量、关键帧选择阈值、图像分辨率、帧率、是否启用本地 BA。

### 5.2 子图生成与发送

每个机器人在运行过程中持续构建子图。当满足以下条件之一时，将子图发送到边缘端：

- 关键帧数量达到阈值。
- 运行时间达到固定间隔。
- 位姿不确定性超过阈值。
- 检测到潜在闭环或进入新区域。
- 边缘端主动请求补充数据。

子图内容建议包含：

- 子图 ID、机器人 ID、时间戳和局部坐标系。
- 关键帧位姿、图像摘要或特征描述子。
- 局部地图点、点云或稀疏结构。
- 协方差、不确定性和质量评分。
- 与上一子图的里程计约束。

### 5.3 边缘端子图拼接

边缘端接收子图后，将其作为全局位姿图中的节点。子图之间的重叠匹配结果、里程计关系和闭环关系作为边。

子图拼接流程：

1. 对接收子图进行完整性校验和时间同步。
2. 根据子图描述子、词袋模型、点云特征或神经网络特征检索候选重叠子图。
3. 对候选子图执行几何验证，例如 PnP、ICP、NDT 或特征匹配。
4. 估计子图间相对位姿变换和约束协方差。
5. 将可靠约束加入全局位姿图。
6. 触发局部优化、滑动窗口优化或全局优化。

机器人端可采用轻量直接匹配或传统特征匹配；边缘端可使用神经网络特征、学习式场景检索或更复杂的几何验证方法。

### 5.4 后端优化策略

边缘端维护全局位姿图或因子图：

- 节点：机器人位姿、关键帧、子图位姿或地图锚点。
- 边：里程计约束、子图匹配约束、闭环约束、IMU 预积分约束、GPS/先验约束。
- 优化器：Ceres Solver、g2o、GTSAM。

优化策略：

- 实时阶段使用滑动窗口优化，保证地图更新频率。
- 闭环触发时执行局部图优化，并异步调度全局优化。
- 对多机器人场景引入机器人间相对约束。
- 对网络延迟导致的乱序子图采用时间戳和版本号进行增量融合。
- 对低置信度约束使用鲁棒核函数，降低错误闭环影响。

## 6. 通信与传输设计

### 6.1 DDS 通信原则

系统通信层采用 DDS，底层优先使用 UDP/IP 与 RTPS，不依赖 TCP。DDS 负责发布-订阅、QoS 策略、可靠性控制、发现机制和安全策略。

推荐配置：


| 数据类型    | 传输方式             | QoS 建议                | 说明         |
| ------- | ---------------- | --------------------- | ---------- |
| 位姿状态    | DDS Topic        | Reliable + KeepLast   | 低带宽、高重要性   |
| 关键帧/子图  | DDS Topic        | Reliable + Deadline   | 需要完整性保障    |
| 图像/视频帧流 | DDS Topic + x265 | BestEffort 或 Reliable | 根据网络状态自适应  |
| 控制策略    | DDS Topic        | Reliable + LowLatency | 边缘端下发，要求稳定 |
| 监控指标    | DDS Topic        | BestEffort            | 可容忍少量丢失    |


### 6.2 零拷贝与共享内存

在同机多进程或同边缘节点内部，优先使用 DDS Shared Memory Transport 或 Iceoryx 类机制，减少跨进程拷贝。

典型路径：

```text
SLAM 前端输出
  -> 共享内存缓冲区
  -> 传输模块读取元数据
  -> 编码 / 序列化
  -> DDS 发布
```

### 6.3 x265 编码策略

x265 用于压缩图像或帧流，降低局域网和边缘链路上的带宽压力。编码参数由 PPO 策略或规则基线动态调整。

可调参数：

- 分辨率。
- 帧率。
- CRF 或码率。
- GOP 长度。
- 是否只发送关键帧、ROI 或特征区域。
- 是否发送原始图像、压缩图像、特征描述子或混合数据。

## 7. DRL/PPO 决策框架

### 7.1 决策目标

PPO 智能体不直接替代 SLAM 算法，而是作为系统级调度器，优化通信、计算卸载和资源分配。

主要决策对象：

- 不同模块的传输优先级。
- 图像压缩率、码率和帧率。
- 特征提取等级和关键帧发送频率。
- 前端、本地 BA、边缘 BA 和全局优化之间的任务分配。
- 多机器人之间的边缘计算资源配额。

### 7.2 状态空间

状态应覆盖网络、计算、地图质量和机器人状态。


| 状态类别    | 典型变量                          |
| ------- | ----------------------------- |
| 网络状态    | 带宽、延迟、抖动、丢包率、队列长度             |
| 节点负载    | CPU、GPU、内存、温度、推理队列长度          |
| SLAM 状态 | 轨迹不确定性、地图一致性评分、待处理子图数量、闭环候选数量 |
| 机器人状态   | 电量、速度、任务紧急度、局部环境复杂度           |
| 系统状态    | 当前模型版本、任务优先级、边缘节点可用容量         |


### 7.3 动作空间


| 动作类别 | 典型动作                      |
| ---- | ------------------------- |
| 传输控制 | 调整模块优先级、发送频率、压缩率、编码质量     |
| 感知控制 | 调整特征数量、图像分辨率、关键帧阈值        |
| 计算卸载 | 调整卸载比例、是否启用本地 BA、是否延迟全局优化 |
| 资源调度 | 为不同机器人分配边缘计算资源和队列优先级      |


### 7.4 奖励函数

奖励函数需要平衡精度、延迟、带宽、能耗和稳定性。

```text
reward =
    w_accuracy * map_consistency_gain
  - w_latency  * latency_penalty
  - w_loss     * packet_loss_penalty
  - w_energy   * energy_cost
  + w_bandwidth * bandwidth_efficiency
  - w_switch   * action_variance_penalty
```

建议约束：

- 地图精度优先级高于带宽节省。
- 对频繁切换动作进行惩罚，避免系统抖动。
- 网络恶化时允许降低帧率或特征等级，但不能破坏定位连续性。
- 机器人低电量时提高能耗惩罚权重。

### 7.5 训练与推理分离

在线实时系统以推理为主，训练应放在云端或异步边缘任务中。

- 机器人端：执行轻量规则策略或边缘端下发策略。
- 边缘端：执行低延迟 PPO 推理，目标推理延迟小于 10 ms。
- 云端：进行离线训练、仿真评估、超参数优化和模型注册。
- 模型更新：采用影子模型验证、热更新和可回滚发布流程。

## 9. 系统工作模式

### 9.1 正常操作模式

- 机器人持续建图，边缘端实时融合和优化。
- PPO 根据网络状态和负载动态调整编码、传输和卸载策略。
- 边缘端维护全局地图和多机器人一致性。
- 监控系统持续记录延迟、吞吐、地图质量和模型表现。

### 9.2 训练模式

- 边缘端收集真实运行经验。
- 云端使用仿真和真实经验进行离线训练。
- 新模型先在仿真环境评估，再进行 A/B 测试。
- 通过影子部署和热更新实现平滑切换。

### 9.3 降级模式

- 网络中断时，机器人端使用本地轻量 SLAM 和缓存机制自主运行。
- 边缘节点故障时，机器人端执行保守策略，降低采样和发送频率。
- 通信恢复后，机器人端增量上传缓存子图，边缘端进行补偿优化。
- DRL 推理超时时，系统回退到规则基线策略。

## 12. 部署架构

### 12.1 单边缘节点部署

```text
[机器人集群] <--DDS/局域网--> [边缘服务器] <--Internet--> [云端训练与模型管理]
```

适用于实验室、单园区、单楼宇或小规模机器人集群。

### 12.2 多边缘节点联邦部署

```text
                 [云端协调中心]
                       │
           ┌───────────┴───────────┐
           ▼                       ▼
       [边缘节点 A]             [边缘节点 B]
           ▲                       ▲
       [机器人组 1]             [机器人组 2]
```

适用于多区域、多楼层或多站点系统。边缘节点之间同步地图摘要、模型版本和必要的全局约束。

### 12.3 混合云-边部署

```text
[公有云：训练/仿真] <--同步--> [私有云：敏感数据] <--同步--> [边缘集群：实时处理]
```

适用于对数据安全和实时性均有要求的生产环境。

## 13. 架构创新点

- 分层异构计算：机器人端处理轻量前端，边缘端处理子图优化、闭环和全局 BA。
- DRL 驱动自适应系统：根据网络质量、计算负载和地图质量动态调整系统参数。
- DDS + 零拷贝 + x265 传输：兼顾实时性、带宽效率和可靠性。
- 云-边-端协同训练：端侧运行、边缘决策、云端训练，形成持续优化闭环。
- 可生产化部署：包含模型版本管理、A/B 测试、监控告警、降级和回滚机制。

## 14. 演进路线

### 阶段 1：核心功能验证

- 搭建基础 SLAM 前端与边缘端接收链路。
- 实现点对点 DDS 通信。
- 完成基础子图生成、发送和边缘端融合原型。
- 搭建简单规则控制器，作为 PPO 策略的基线。

### 阶段 2：系统集成

- 接入完整分层 SLAM 架构。
- 实现子图拼接、局部优化和全局位姿图优化。
- 集成 LibTorch 推理能力。
- 建立基本监控、日志和指标采集。

### 阶段 3：训练系统开发

- 构建仿真训练环境。
- 实现 PPO 智能体、经验收集和训练流程。
- 支持分布式训练和超参数搜索。
- 建立模型评估、版本管理和热更新机制。

### 阶段 4：生产就绪

- 完成高可用、容错和降级模式。
- 加强 DDS Security、传输加密和访问控制。
- 建立 A/B 测试与灰度发布机制。
- 使用容器化和边缘集群进行部署。

### 阶段 5：智能增强

- 支持多智能体协作与跨边缘节点地图同步。
- 引入预测性维护和异常检测。
- 优化多场景泛化能力。
- 逐步形成可持续自演进的边缘智能系统。

## 15. 当前优先级建议

短期重点不宜直接铺开全部 DRL 和生产化能力，应先验证 SLAM 与通信主链路。

1. 先完成机器人端子图结构定义、DDS Topic 设计和边缘端接收链路。
2. 再实现子图拼接、闭环候选检索和位姿图优化。
3. 建立规则基线策略，采集网络、计算和地图质量指标。
4. 在规则基线稳定后接入 PPO 推理，并使用仿真环境训练初版模型。
5. 最后补齐模型管理、A/B 测试、监控告警和容器化部署。

## 16. 价值总结

该系统将机器人 SLAM、边缘计算、DDS 实时通信和深度强化学习结合起来，使机器人端保持轻量，边缘端获得全局优化能力，云端持续提升策略质量。最终目标是在动态网络和异构算力条件下，实现低延迟、高精度、可扩展、可持续优化的空间导航系统。
